StrangeChess

A chess engine written from scratch in C#. It uses magic bitboards, alpha-beta search and a tapered evaluation, with no chess libraries. The same code runs on this page, compiled to WebAssembly, so you can play it below.

    Inside the engine

    Alpha-beta search, magic bitboards and a tapered evaluation

    What happens between your move and its reply.

    Alpha-beta pruning, step by step

    The engine looks ahead through a tree of moves. Squares are positions where it picks the best score for itself; circles are where the opponent picks the worst. Once a branch provably can't change the answer, it stops looking at it.

    Magic bitboards

    The board is stored as 64-bit integers, one bit per square. For a rook, the pieces in its way are masked, multiplied by a precomputed "magic" number and shifted. The result indexes a table that already holds every square the rook can reach.

    Click squares to add or remove blockers. The magic number and shift are the engine's own values for a rook on d4.

    Negamax with alpha-beta

    One search function for both sides: a position's score for one player is the negative of the other's.

    Iterative deepening

    It searches to depth 1, then 2, then 3 and so on until time runs out, so there is always a finished answer to play. From depth 3, each search starts in a ±50 centipawn window around the last score and widens only if the score lands outside it.

    Transposition table

    1,048,576 slots keyed by a Zobrist hash. A position reached by a different move order is looked up instead of searched again, and its stored best move is tried first.

    Null-move pruning

    The engine gives the opponent a free move. If the position still beats the cutoff, the real search is skipped. It's turned off in check and when the side to move has only pawns left, where passing can be the best move.

    Late move reductions

    Quiet moves after the first four are searched 1 to 2 plies shallower. If one scores better than expected, it gets a full-depth re-search.

    Move ordering

    The move stored in the transposition table goes first, then captures sorted by most valuable victim and least valuable attacker, then two killer moves per ply. Better order means earlier cutoffs.

    Quiescence search

    At the end of the main search it keeps following captures and promotions, so it doesn't stop scoring halfway through a trade.

    Tapered evaluation

    Separate middlegame and endgame piece-square tables, blended by the material left on the board. The king shelters early and walks to the centre late.

    Positional terms

    Bishop pair, rooks on open files and the seventh rank, doubled, isolated and passed pawns, the king's pawn shield, development and castling.

    Mop-up evaluation

    When it's ahead in an endgame, it pushes the losing king to the edge and brings its own king closer, to help turn winning positions into mates.

    Repetition detection

    A history of Zobrist keys spots repeated positions inside the search and scores them as draws.

    UCI protocol

    It speaks the Universal Chess Interface, so it works with UCI chess GUIs such as cutechess. The console next to the board shows the same kind of output.
